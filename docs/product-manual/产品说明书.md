# OfferPilot 产品介绍与用户指南

适用版本：本地部署 `0.1.0` 开发快照（主体截图：2026-09-07，主线 `46fa54a`，修复至 `46339af`；日程、复习补图及入口核对：2026-09-08，`389634f`；Offer 状态、经历素材和长草稿补图：`1223237`；准备依据、简历建议与练习依据补图：`69222a4`）。最近更新：2026-09-08。

新版配图沿用原案例的筱哲简历、星澜智能和远帆科技岗位资料：准备建议复用原已保存记录；简历提案与五轮模拟面试、复盘重新调用真实 AI 生成。人物、公司与指标不变，模型措辞和追问可能与旧图不同。其他流程图保留各自的截图版本说明。

OfferPilot 用于整理求职过程中的简历、投递记录、面试安排、复盘和 Offer。你可以围绕一个目标岗位准备材料、记录进展，并整理面试中需要继续练习的问题。

你可以直接在页面中操作，也可以通过 Pilot 提出部分操作请求。出现系统确认卡后，先核对将要保存的内容，再决定是否执行。使用 AI 生成内容时，请核对经历、数字和表达，再决定是否采用。

本指南先介绍主要功能和开始使用的方法，再按求职场景说明具体操作。文中的人物、公司和资料均为示例，不限定项目适用的职业方向。

> 这是开发快照指南，不是针对所有 `0.1.0` 构建的兼容性承诺。不同版本可能调整界面或入口；与使用相关的差异会就近标注。安装方法以对应版本的仓库 README 为准。

## 1. 了解 OfferPilot

### 1.1 从一个岗位出发，整理整段求职过程

你可以先创建一条投递记录，把岗位描述、准备材料、面试安排和后续结果放在同一条求职主线上。已有多条投递时，用看板或列表查看进度，而不是在不同聊天和表格里寻找记录。

![投递工作区：同一看板中查看公司、岗位和阶段](screenshots/R03-05-page-create-saved.png)

OfferPilot 主要帮助你完成这些事情：

- 整理简历与岗位资料，生成并审阅岗位专属投递材料。
- 记录投递进度和面试安排，准备问题并进行文字模拟。
- 保存面试复盘，把确认的练习重点用于专项练习和下一轮准备。
- 整理可复用的经历素材与学习参考资料。
- 收到 Offer 后整理待遇、比较已知条件、准备谈薪并记录决定。

例如，一轮面试结束后，你可以把“不清楚的指标定义”保留为练习重点，再将其用于下一场面试准备。这是不同功能之间的衔接，不是系统自动替你完成学习。

![结果示例：将所选复盘重点用于下一轮准备](screenshots/R07-17-feedback-to-preparation.png)

收到多个 Offer 时，可以把月薪、薪数、福利和答复期限放在一起查看。比较帮助整理事实，最终决定仍由你做出。

![结果示例：横向比较两份 Offer，展示对比区域](screenshots/P01-01-offer-comparison-crop.png)

### 1.2 页面与 Pilot：两种入口，共同核对结果

你可以直接填写页面表单，也可以让 Pilot 帮你提出修改。两种入口最终都应回到业务页面核对保存结果。

| 入口 | 怎么操作 | 什么时候算完成 |
|---|---|---|
| 页面 | 打开对应功能，填写表单，点击保存 | 页面显示保存结果，重新打开仍能读到 |
| Pilot / Haru | 用中文说明需求，核对真正的系统确认卡，批准操作 | 确认执行后，在业务页面读到正确结果 |

Haru 是助手的角色呈现入口，Pilot 也提供完整会话工作区。模型正文中写出的“按钮”“卡片”或“已联动”，不等于页面实际存在这些控件或已完成相应操作。

本指南按默认的人工确认方式说明 Pilot 写入：核对目标记录与字段，在真正的系统确认卡上批准，再回到业务页面查看结果。只读查询、待确认建议和已经执行的写入是不同状态；拒绝和撤销的区别见[助手操作](#s11)。

### 1.3 数据与决定由你掌控

本地部署将业务数据保存在本机工作区。需要 AI 时，相关资料会按功能提示发送给你配置的模型服务；“本地保存”不等于“所有 AI 计算都在本地完成”。不要提供无关敏感资料，也不要把密钥或完整备份放进公开仓库。

OfferPilot 不自动向招聘方投递或发送消息。生成材料、保存谈薪草稿、记录接受 Offer，均不代替你的外部沟通和最终决定。

## 快速开始：先记录一个岗位，再体验 AI 辅助

### 开始前准备什么

先按[截图基线版本的安装说明](https://github.com/offercontext/offerpilot/blob/46339af9a5796d3f9ecc7da2fb881c19a0df49b4/README.md#快速开始)安装并启动项目；使用更新版本时，请改看[最新 README 的快速开始](../../README.md#快速开始)，并核对版本差异。README 维护 Docker 与源码启动方式、访问地址和数据目录，本指南不重复维护另一套部署命令。

| 想做的事情 | 需要准备 |
|---|---|
| 页面记录投递、保存 JD、手动编辑资料 | 一个真实岗位的公司、职位和岗位描述；不必先配置 AI |
| 上传简历并手动核对 | 你自己的 PDF 简历；删除无关敏感信息 |
| AI 分类、材料生成、面试建议或 Pilot 对话 | 可用的模型服务、对应连接配置与密钥，以及本次要使用的资料 |

如果选择源码方式，先按 README 准备其命令所需的 Git、uv 和 Node.js/npm；选择 Docker 方式则准备可用的 Docker 环境。具体平台与依赖要求应随所用版本的安装说明核对。本指南描述本地部署界面，不等同于托管网站的功能说明。

### 第一次使用：保存一条投递与 JD

这条路线不需要先了解全部模块，也不要求先使用 AI。

1. 打开应用，进入投递看板，点击添加投递。
2. 填写公司和岗位，选择符合实际进度的状态后保存。
3. 打开刚创建的投递，在准备区域添加岗位描述，保存 JD。
4. 返回看板再打开这条记录，核对公司、岗位、状态和 JD。

完成标志：你能重新打开同一条投递，并看到刚保存的岗位资料。完整表单和结果截图见[创建投递与补充岗位资料](#s03)。到这里，你已经可以用 OfferPilot 跟进一个真实岗位。

### 下一步：让 AI 帮你准备这次投递

1. 进入素材库，上传并核对简历，保留原始文字，见[简历管理](#s02)。暂未配置 AI 时，不必立即进行 AI 分类。
2. 从左侧“设置 → AI 与模型 → 配置 AI”打开 AI 设置，按下表填写供应商信息。先“测试连接”，再“应用到 Provider 列表”，需要时设为默认，最后点击页面顶部“保存”。测试成功和应用到列表都不等于配置已保存。
3. 需要 AI 分类时，回到简历中明确授权，逐项核对候选后保存。
4. 打开目标投递的准备入口，选择本次简历，核对 JD，生成材料包。
5. 检查经历、数字和表达，再保存材料草稿或确认创建岗位简历版本，见[岗位专属材料](#s04)。

连接测试成功只代表当前连接可用，不保证每次业务生成都会成功。模型调用可能产生供应商费用；提交前留意页面提示的资料范围。出现错误时，先看[常见问题](#s12)，不要反复批准同一笔不确定结果的写入。

| 字段 | 应填写什么 |
|---|---|
| API 密钥 | 当前模型服务为你签发的密钥；不要贴进聊天、截图或反馈附件 |
| 模型供应商、接口地址 | 供应商要求的协议适配类型与 API 基础地址；不是官网首页地址 |
| 模型 | 供应商实际支持的模型 ID，不是自行起的显示名称 |
| 上下文窗口、单次最大输出 | 按该模型官方额度填写 token 数；输出上限须留出输入和协议空间，不照抄示例数值 |
| 配置 ID、显示名称及开关 | 前两项用于区分配置；按需启用，原生 JSON Schema 仅在服务支持时开启，写操作自动确认保持默认关闭 |

表单下方有“测试连接”和“应用到 Provider 列表”；页面顶部的“保存”才会持久保存配置。保存后可重新打开检查默认供应商。

![AI 连接测试结果局部；填写规则见上表](screenshots/P-start-ai-test-result.png)

完成标志：业务页面中能读到你核对后的材料，基础简历仍保留。保存草稿不是向招聘方发出消息。

### 本指南的示例案例

后续步骤以“筱哲的求职之旅”贯穿说明：星澜智能用于页面材料与复盘示例，远帆科技用于 Pilot、文字模拟与 Offer 对比，云岚数据用于投递创建和撤销。筱哲的技术背景只是示例，你可以替换成自己的岗位和真实经历。

示例将未来面试模拟为已结束以说明后续流程。实际使用时按真实进度标记完成，不要照抄日期、薪酬或项目数字。

## 2. 导入、核对与编辑简历

当你想集中维护基本信息、工作经历和岗位版本时，从素材库的简历页开始。先保留原文，再核对结构化内容；完成后可在简历库和编辑器中查看保存结果。

### 2.1 上传 PDF，保留原文

上传前确认 PDF 含可提取的文字；扫描件暂不支持 OCR。进入素材库的简历页，选择上传 PDF，核对文件名后上传；单个 PDF 最大 10MB。

![打开 PDF 上传窗口](screenshots/02-02-upload-pdf.png)

上传后先提取文字，提取成功不等于已经完成结构化整理。需要 AI 帮忙时再进入“AI分类并核对”；不使用 AI 时，关闭分类弹窗，从素材库的简历列表点击该简历的“编辑”，对照“PDF提取原文”手动填写各模块，最后点击顶部“保存”。

![原文已提取，等待分类核对](screenshots/02-03-import-review-entry.png)

### 2.2 可选：授权 AI 分类，逐项核对后保存

1. 阅读发送给 AI 的内容范围，明确同意分类。
2. 等待候选项返回，检查基本信息、教育、工作、项目和技能。
3. 对照原文取消不合适的候选或修正内容，再确认填入空白模块。

![明确同意发送提取文字进行分类](screenshots/02-04-ai-classification-consent.png)

![对照原文核对勾选项，完成后点击底部“确认填入空白模块”](screenshots/P02-01-classification-crop.png)

### 2.3 结构化编辑与检查

AI 分类确认后，或直接手动整理时，都可以从简历列表点击“编辑”，按基本信息、教育经历、工作经历、项目经历和技能等模块修改，再点击顶部“保存”。手动编辑不要求先配置 AI。示例后续修改了联系方式；请将每项内容换成自己的真实资料。

![在表单中核对和编辑工作经历](screenshots/02-09-structured-experience.png)

![手动修改基本信息](screenshots/R02-01-resume-manual-edit.png)

“事实体检”帮助检查结构和可观察字段，不是外部真实性认证。结构完整度达到 100%，也不等于经历真实、表达优秀或一定能通过筛选。

![查看事实体检结果](screenshots/02-10-fact-check.png)

### 3.1 页面创建

检查系统确认卡中的公司、岗位、状态和目标操作，再点击确认新建。模型可能先做文字核对；聊天中回答“确认”与点击真正的写入确认卡不是同一件事。

## 4. 生成岗位专属投递材料

需要针对一个岗位调整表达、准备沟通正文时，从该投递的准备入口选择简历和 JD。AI 提供可审阅建议，你决定保留什么；保存结果在材料工作区或岗位简历版本中查看。

### 4.1 选择简历并生成材料包

打开投递准备，选择本次使用的简历，核对带入的 JD，再请求 AI 生成。生成结果需要人工审阅，不会自动替你向招聘方投递。

![选择简历并核对当前投递的 JD](screenshots/04-01-material-input.png)

![材料包中的简历优化建议，沟通话术和清单见下一图](screenshots/04-03-material-generated.png)

### 4.2 检查话术与改写

沟通话术可继续编辑。核对每个经历、数字和承诺，只保留你能证明的内容；保存草稿不等于发送消息。

![人工检查沟通正文与投递清单](screenshots/04-04-material-message.png)

简历改写应逐项比较前后内容和来源。如果建议新增了你没有做过的工作，不要直接接受。

![星澜智能岗位简历建议正文：保留800ms至300ms的原始指标，中文显示修改位置与来源](screenshots/R08-resume-proposal.png)

### 4.3 保存岗位版本，保留基础简历

确认接受后，本次流程创建岗位专属版本，不覆盖基础简历。保存后核对投递准备使用的版本是否正确。

## 5. 安排日程与面试提醒

需要跟进面试或其他时间节点时，为对应投递安排日程，并在日历核对时间与提醒。日程记录负责安排事项，不自动代表投递阶段已改变。

### 5.1 页面安排面试

从投递详情点击安排日程。核对已带入的投递，选择事件类型和轮次，填写日期、开始时间、时长、地点和准备事项，创建后回到日历检查。

![为星澜安排下一轮技术面试](screenshots/R05-01-next-interview-form.png)

![同一条星澜智能二面：9 月 12 日 14:00–15:00](screenshots/P05-02-second-interview-calendar.png)

提醒时间字段不触发桌面、短信或邮件通知。要记录提醒时间，打开同一日程的“调整时间”，保持 9 月 12 日 14:00、轮次 2 不变，将提醒时间填写为当天 13:30 后保存。

![同一条二面日程：开始 14:00，提醒字段 13:30](screenshots/P05-03-second-interview-reminder.png)

## 7. 从复盘走到下一轮准备

当面试暴露出需要继续练习的问题时，先记录原始复盘，再选择值得保留的建议。按下面路线可以把一次面试的经验用于下一次准备，而不必把所有 AI 建议都保存下来。

### 7.1 面试结束后记录原始复盘

按真实进度标记面试完成，再从投递详情进入复盘。记录被问到的问题、实际回答、自我反思和难点，保存原始内容后再考虑 AI 建议。

![填写问题、表现与待改进点](screenshots/07-04-review-filled.png)

### 7.2 生成或恢复建议

AI 建议与原始复盘分开。阅读表现总结、练习重点和待澄清问题时，应检查其引用是否对应自己的原始记录。

![查看带引用的复盘建议](screenshots/R07-08-review-advice.png)

若出现“结果待确认”，不要据此认定服务端一定没完成，也不要连续新建生成任务。打开该投递详情的“准备”页，找到下方“面试 → 面试复盘”，在原复盘记录旁点击“复盘建议”，进入“面试复盘建议”面板；保持来源不变，滚动到面板底部，点击“生成复盘建议”，继续原尝试。按钮此时仍叫“生成复盘建议”，不是另有一个“恢复”按钮。也可先查看面板内历史建议；恢复后核对结果是否对应原复盘。若来源已改变，按钮变为“重新生成复盘建议”，这会新建尝试，不属于原任务恢复。

![恢复本次生成任务后显示已生成的建议](screenshots/R07-11-original-attempt-recovered.png)

### 7.3 选择重点并确认保存

挑选要继续练习的重点，补充自己的行动备注，再在系统确认区保存。看到 AI 建议不等于重点已经保存。

![明确确认保存本次准备重点](screenshots/R07-12-confirm-next-focus.png)

把已保存重点关联到下一轮面试，核对创建内容后确认。该创建步骤不调用 AI；回答与自我反馈是你的练习记录，不是自动评分。

![完成后在历史中查看练习记录](screenshots/R07-16-practice-completed.png)

### 7.5 带入下一轮准备

打开下一场面试准备，重新核对简历和 JD，明确选择上一轮保存的复盘重点。不要假定所有历史内容会自动带入；已撤销的重点不应继续作为本次选择。

![明确选择上一轮复盘重点](screenshots/R07-13-next-preparation-source.png)

这条路线是“记录复盘 → 阅读建议 → 确认重点 → 专项练习 → 下一轮准备”。完成后，在下一场面试准备中查看所选重点的应用结果；每一步仍需要你的选择、回答与核对。

### 11.4 搜索、归档与停止

在 Pilot 搜索历史会话并打开，可以回看原始讨论。历史“保存成功”消息记录的是当时的操作，撤销之后应以业务页面当前状态为准。

![搜索并打开云岚的历史会话](screenshots/R10-03-conversation-search.png)

已结束会话可以重命名并归档，再从已归档列表找回。归档会话不删除业务记录，也不会重放历史操作。

![在归档列表找回整理后的会话](screenshots/R10-04-conversation-archive.png)

点击停止后，你可以重新输入。停止不会撤销已经保存的修改，也不保证后台请求已经结束。

![停止本轮回复后恢复输入](screenshots/R10-06-stopped.png)

## 12. 设置、数据与使用边界

设置集中管理 AI、数据、Haru 外观和语音资源等项目。需要减少动画干扰时，进入设置的 Haru 与外观区域，将动画级别改为简洁；回到工作区检查显示效果。角色出现安全占位状态时，不要据此判断业务记录丢失。

需要保留数据副本时，进入设置的数据与备份区域，选择导出完整数据，并在浏览器下载位置检查文件。备份可能包含敏感配置，应存放在自己的安全位置，不放进公开仓库，也不作为问题反馈的默认附件。

恢复备份可能覆盖目标环境，应先核对所用版本的恢复说明与目标数据，不在唯一工作副本上试验恢复。离线语音另需按界面提示准备资源，不是文字输入或普通数据管理的前置条件。

### 常见情况怎么处理

| 看到的情况 | 建议操作 |
|---|---|
| 模型说“已保存”，但没有正式回执 | 检查是否仍有待确认卡，回业务页查看保存结果，不只凭聊天文字判断 |
| 修改确认后，模型建议恢复旧值 | 拒绝不需要的额外提案，检查实际保存值 |
| 生成显示结果待确认 | 查看历史或恢复本次生成任务，避免连续新建重复请求 |
| 面试准备不可用 | 先确认对应 JD、简历和事件是否齐备 |
| 更新状态后列表不见了 | 检查并清除旧状态筛选 |
| 日历时间与确认不一致 | 核对时区和业务页面，需要时通过页面明确修正 |
| 没有撤销按钮或撤销失败 | 不假定数据已恢复；查看当前状态，只在明确支持的操作上撤销 |
| AI 建议含陌生经历、数字或承诺 | 对照来源删除或修改，不当作个人事实或直接对外发送 |
