# Desktop Workspace Experience Redesign 设计

## 目标与边界

本阶段把 OfferPilot 桌面端从功能目录收敛为围绕求职过程的工作台：今日、投递、面试、资料，以及独立弱入口设置。第二阶段固定基线为 `2f6e895e02b86f33052a2e507e9b0404bb82f4b5`，只修改 `web/**` 和本任务的规格、计划、报告；不修改后端、领域模型、API、SSE、Agent、Pending/HITL 或 Journal 语义。

验收覆盖主要桌面 `>=1180px` 与紧凑桌面 `768-1179px`。保留现有移动 fallback，但不新增移动产品形态。继续使用 React 18、Ant Design、CSS Modules、React Query、现有服务与 `AssistantSurfaceProvider`。

## 设计选择

采用“共享业务模型 + 现有页面渐进重排”，而不是重写路由或复制业务数据。确定性展示逻辑拆成纯函数，页面复用已有查询、mutation、Drawer 和 Query Key。这样可以为状态映射、无损转换和渐进披露写稳定测试，也能避免引入第二套控制器或状态源。

视觉语言是高密度、克制、任务优先的桌面作业台：变化度 4/10、动效 2/10、信息密度 7/10。保留现有品牌与 Ant Design；每页最多一个明显主操作；卡片只表达真实层级；动效只用于可中断反馈，并遵守 `prefers-reduced-motion`。

## 信息架构

### 今日

首屏顺序固定为：当前最重要的行动、今日其他待办（最多三条）、未来七天日程、本周进度、默认折叠的数据分析。主行动来自现有确定性 `mission.actions`；同样数据必须得到相同选择。没有足够数据时展示诚实空状态，不生成建议、不新增模型调用。完成后的新手引导不再长期占据首屏。

### 投递详情

顶部只保留公司/岗位、阶段、最近下一步时间、一个阶段主按钮和“更多操作”。状态映射为：待投递→完善投递材料、已投递→设置跟进时间、笔试→准备笔试、面试→准备本轮面试、Offer→查看 Offer 与截止时间、结束→记录结果与经验；有已完成面试而尚未进入 Offer 时，面试阶段可显示“完成面试复盘”。

正文按概览、岗位与材料、日程与沟通、面试、结果分区。低频与危险动作进入更多菜单，危险确认不弱化。AI 文案统一为“让 Haru 帮我”，通过已有 `onAskPilot` 进入统一 Assistant Surface，并继续由 AppShell 提供可信 application page context；复杂任务展开到 Pilot。

### 面试与练习

入口组合为待准备、模拟练习、题库、复盘与成长。只组合页面入口：面试索引、题库、练习、复盘、故事、Knowledge 和语音状态继续使用原服务、Query Key 与领域边界。旧 `interview`、`questions` 等 ViewMode 仍映射到这一模块；页面组合不会触发 Story/Knowledge 自动串写。

### 资料与简历

资料模块标签为简历、经历与故事、学习资料。简历编辑默认采用结构化字段：基本信息、教育、工作、项目、技能和其他现有字段，支持条目增删、排序、字段校验、保存、取消与未保存确认。高级 JSON 是次级入口。

结构化转换以原 `content_json` 为基底做 patch：已知字段更新，顶层、`career_intent` 和各条目中的未知字段原样保留。无法解析或类型不兼容的历史值进入只读恢复/高级编辑，普通表单不得用空值覆盖。保存前执行 round-trip 校验。用户文案使用“初稿”“上传现有简历”；样例入口放入低频菜单。

Knowledge 只替换可见语言：来源依据、资料导读、保存版本、内容整理、处理记录。内部 ID、字符坐标和任务状态进入“技术详情”，API 名、类型名和服务名保持不变。

### Offer

零份时只展示录入引导；一份时展示事实、截止时间、待确认字段与下一次沟通，不展示比较维度；两份及以上才显示比较选择入口；只有用户主动进入比较后才加载和显示维度管理。缺失值展示为“待确认”，不得伪装为 0。

### 设置

设置页统一为 AI 与模型、数据与备份、Haru 与外观、语音、高级与诊断。顶栏齿轮直接进入设置页的 AI 与模型分区。`AISettingsDrawer` 的能力可作为设置页内容继续复用，但不保留独立页面状态源；供应商、Fallback 和日志放在适度折叠区域。备份/恢复提示与 Haru preference 保持原行为，诊断和快照不得包含 API Key。

## 路由与 Assistant 不变量

一级业务导航只有今日、投递、面试、资料，设置单独弱化呈现；Pilot 不进入一级导航。旧 ViewMode 仍有明确模块映射。看板和列表继续共享 `ApplicationViewState`，保留搜索、筛选、排序、选择和 URL 参数。所有页面 AI 入口只能沿既有 `AssistantSurfaceProvider`/controller 传递，不新增 Chat service、SSE parser、Pending/HITL 操作或 Journal UI 状态。

## 错误与恢复

数据查询失败保留重试入口；空数据不制造统计或建议。结构化简历出现非法历史数据时阻止普通保存，展示原始内容恢复路径。危险删除继续保留确认。设置日志刷新失败继续展示上一页结果。路由兼容通过显式映射测试固定，未知 ViewMode 不静默吞掉。

## 测试策略

纯函数测试覆盖今日主行动、阶段动作、简历无损 round-trip 与 Offer 展示状态；组件测试覆盖页面主操作、默认折叠、面试入口、设置唯一入口和键盘焦点；源码/AST 风格门禁覆盖控制器、Chat/SSE、Journal、Pending/HITL、后端 diff、移动依赖和设计系统依赖。合成 Golden 不含用户内容、密钥或真实业务数据。最终运行完整前端测试/build、后端兼容 gate、静态 smoke，并用内置浏览器检查 768、1024、1440 宽度和完整业务链。

## 非目标与集成

本阶段不实现 Compact Confirmation、主动提醒、持久去重、Journal Run UI、SSE replay、后台 Agent Queue、移动端或领域模型合并。Pilot Runtime 尚未合入，因此当前 integration baseline 记为“待集成”；其合入 main 后，本分支再更新并重新执行组合 gate，不在本阶段提前 merge。
