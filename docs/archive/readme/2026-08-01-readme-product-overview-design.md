## 1. 目标

将当前偏技术清单的 README 重写为普通求职者能在约十五秒内理解的产品首页：OfferPilot 是什么、能帮助完成哪些求职工作、Pilot 如何协作，以及如何快速开始。

README 不是飞书产品说明书、完整功能手册、路线图或架构文档。它应简短、准确、可验证，不为营销而宣称尚未发布或未通过验收的能力。

## 2. 读者与产品口径

目标读者是普通求职者，而不是仓库维护者或后端贡献者。README 使用中文为主、英文精简版为辅。

产品口径固定为：

- OfferPilot 是本地优先的 AI 求职工作台；
- 用户可管理简历、投递、岗位评估、材料、面试准备、模拟面试、复盘、知识、Offer 与谈薪；
- Pilot 在当前上下文中协作，写入前需要用户确认；
- 产品给出建议、帮助整理和准备，不自动投递、不自动执行外部动作，也不替用户决定接受或拒绝 Offer；
- 本地数据使用 SQLite；AI 仅在用户配置 Provider 后、由用户主动触发时使用。

不得以 README 宣传尚未合入主分支的 Offer 谈薪重构、Application Journey 面板、外部薪酬检索、自动投递、Offer 排名或录用预测。

## 3. 信息架构

README 的中文主段严格控制为以下八个区域：

1. **标题与一句话定位**：`OfferPilot — 本地优先的 AI 求职工作台`，后接一句面向结果的说明。
2. **它能帮你做什么**：一小段说明与五项短能力，不写功能穷举。
3. **真实界面**：五张中文、亮色、宽屏的真实本地部署截图；每张一行说明。
4. **Pilot 有何不同**：两到三句话说明上下文、建议与人工确认；不写模型供应商、内部工具或实现细节。
5. **快速开始**：Docker 和源码运行两条最短路径；命令真实可用。
6. **隐私与边界**：本地 SQLite、用户自带 AI 配置、无自动投递/替用户决策。
7. **精简英文版**：英文定位、能力概览、最短启动命令、隐私边界和许可证链接。
8. **许可证**：链接 AGPLv3，不在 README 中展开法律解释。

移除或移至其他文档：长 CLI 清单、完整 JSON 配置样例、技术栈表、历史架构调整、内部阶段路线图、未完成能力列表和重复的 Docker smoke 说明。

## 5. 文案边界

中文标题与能力项使用短句：

- 管理简历与投递；
- 评估岗位匹配、准备投递材料；
- 准备面试、进行文本模拟与复盘；
- 汇总已确认的经验与知识；
- 比较 Offer 已知事实，准备谈薪沟通。

Pilot 说明使用“在当前上下文中协作”“展示建议和确认卡”“由你决定是否执行”等措辞。不得使用“自动完成投递”“替你筛选最优 Offer”“保证拿到 Offer”“智能决策”“无需确认”等表述。

用户的公司、岗位、简历标题、Offer 备注、证据摘录和 AI 可验证内容保留原文，不被 README 文案强制翻译或改写。
