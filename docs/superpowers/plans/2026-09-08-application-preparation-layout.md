# 投递准备页布局实施计划

**目标：** 按用户提供的前后预览重排投递详情准备页，让已投递文案、岗位与材料主体、紧凑日程/复盘辅助栏对应实际业务事实。

**架构：** 只调整现有 React 展示与导航入口。保留 ApplicationDetail 的 Query、Task Resolver、CoreTaskSurfaceController、事件状态投影及 HITL owner；不新增后端字段、附件能力、AI 推断或自动写入。

**技术栈：** React 18、Ant Design、CSS Modules、Vitest/jsdom。

**范围更新：** 用户明确不考虑移动端；只验收桌面与桌面窄窗口。手机导航临时修补已撤回。

**依据：** 用户 2026-09-08 的两张截图与六项建议；投递子 PRD revision 68；`2026-08-29-core-task-surface-convergence-design.md`、`2026-08-05-application-jd-versions-design.md`。当前仓库基线 `72be841`。

## 设计边界

- “概览 / 准备 / 进展”不变。宽屏主辅约 2:1，内容宽度不足时恢复单栏，不挤压正文。
- 准备页移除重复的“准备”大标题。岗位描述显示当前 JD 版本与原文，长文可展开；来源为空时没有复制按钮。
- 关联材料只从当前投递材料包读取。简历只称“关联简历”，不以 `submitted` 状态冒充简历不可变快照。城市、薪资、文件大小与附件不从原文推断。
- 已投递材料入口用“查看投递材料”，未投递用“继续准备”；有面试任务时继续按已有 resolver 的事件身份打开准备/复盘。
- 日程空态与复盘空态用简短文字，无可复盘事件不打开空选择器。保留加载、错误、重试、结果未知和外部 pending 状态。
- 顶部详情模式不显示问候与日期，但保留快速打开、设置、返回与阶段主操作。
- 不改数据、不执行真实 AI，不推送。Haru 沿用已有拖动/缩放/隐藏入口，验收透明区域点击和键盘焦点遮挡。

## 实施与验证（已完成）

- 已完成组件、顶栏与 Haru 小尺寸测试的 RED/GREEN；保留状态保护与 task owner。
- 相关回归：34 个文件、373 项测试通过（包含 application tasks、core task surface、assistant surface、mascot）。CR 后新增旧 submitted 标记测试，受影响组件 40 项通过。
- 最终 `npm --prefix web run build` 通过；保留既有大 chunk 提示。`git diff --check` 通过。
- 内置浏览器：独立 8094 合成数据，1440/1920 双栏、1100 单栏均无页面横向溢出；浅色/深色、JD 展开/收起、日程创建后回到准备页、面试事件入口已检查。材料关联/归属错误/空态由组件测试覆盖。
- Haru 在详情页缩为现有 compact 尺寸，保留缩放/拖动/隐藏；没有新增全页面自动避障机制，用户拖动后仍可能覆盖正文。
- 子代理 CR 指出的旧 submitted 标记冒充投递事实问题已修正为“旧投递标记，缺少证据快照”，并通过回归。无后端、真实数据、远端文档或模型调用改动。
- 仅本地独立分支提交，不推送、不合并。

完整发布 gate、Docker 与真实 Provider 验收不属于本轮纯展示改造的默认检查；未执行时在交付中说明。
