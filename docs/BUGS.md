## BUG-1: 面试故事来源选择暴露内部路径，材料难以辨认

**日期**: 2026-09-07
**影响**: 面试故事 Drawer 的来源选择与手工证据选择。

### 现象
页面直接显示 `/content_json/...`、`/turns/004/answer`，大量片段平铺，用户难以区分材料与问答。

### 根因
来源的机器定位路径被同时用作展示标签；模拟面试按单题平铺而非按记录分组。手工证据预览仅查同 attempt 的第一题，可能遗漏后续题目。

### 修复
新增纯展示标签及材料分组层，保留原 kind/id/path；支持搜索、折叠、只看已选及截短预览展开。问题与回答分别选择；底部保留明确 AI 同意，来源变化撤销旧同意。手工证据按完整路径查找。

### 教训
展示身份与业务定位身份分离；过滤不改变勾选，不能把提问当作回答。目标回归覆盖中文映射、精确 payload、空分组省略、冻结选择及重新同意；浏览器只读验收，不触发生成或保存。

## BUG 模板

```markdown
## BUG-N: [一句话现象]

**日期**: YYYY-MM-DD
**影响**: [受影响的功能/用户/版本]

### 现象
[观察到的错误行为,可观察的事实]

### 根因
[真正的原因。不是"症状"。代码层面或设计层面的具体定位]

### 修复
[改了什么。引用 commit hash 或 PR 编号。代码是 ground truth,这里只写关键思路]

### 教训
[下次怎么避免。如果有"不该再被破坏"的规则 → 同步加 RULE-N]
```

## 单条长度

软上限 60 行。复杂多阶段 bug 可超限,需在记录头注明超限原因。
